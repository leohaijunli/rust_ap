# QGC 日志服务修复与只读对照

日期：2026-11-08。工程师报告 SD 日志下载慢、Erase All 不生效、删除后旧列表仍在；授权实现受保护的根目录 `.ULG` 删除，本轮不删除现有卡上的日志。

## 原因

- 原 `LOG_ERASE` 明确返回 `EraseDisabled`，不执行 SD 删除；不能把点击按钮当作成功。
- FAT `File::read` 可在簇边界短读，旧代码把一次短读直接作为一包并按实际长度继续。QGC 5.0.3 只接收 `ofs % 90 == 0` 的数据，错位后续包被忽略，缺块会重请求。
- 路由固定 5 ms 轮询，日志响应又排在已到期遥测后；USB 发送空间和日志队列就绪不能及时唤醒路由。尚未在板上量化各项耗时，不声称 SD 卡本身是瓶颈。

参考：固定依赖 `embedded-fatfs` 的 `file.rs` 读取边界及 QGC 5.0.3 `LogDownloadController.cc` 的包校验、Erase 后立即 Refresh 行为；未移植客户端源码。

## 修改

- 共用 `src/storage/log_files.rs`，填满当前请求包，正常 QGC 数据块维持 90 字节；请求/文件尾段允许短包，剩余字节清零，异常 EOF 报错。
- 日志响应/发送空间事件唤醒路由，仍保留每次队列四帧上限、背压与正常 5 ms 定时调度；不提高 IMU/EKF 的负担预算。
- 新请求在完整包边界取消/接替旧数据请求，关闭旧文件后才执行 END/ERASE；排队的 LIST 在新挂载时恢复链路所有权。
- 删除只在 disarmed、输出关闭、日志停止的管理会话中执行；仅根目录普通 `.ULG` 文件，目录、嵌套日志及其他文件不动。卸载 FAT 并刷新底层流成功后才发送删除数量和空列表；失败/Busy 不返回伪造空卡结果。
