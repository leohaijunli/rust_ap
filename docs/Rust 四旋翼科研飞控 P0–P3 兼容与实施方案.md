# Rust 四旋翼科研飞控:P0–P3 兼容与实施方案

面向 Pixhawk 6X(FMUv6X)、Rust + Embassy、MAVLink / QGroundControl 兼容的开源科研飞控

## 1. 目标与范围

**定位。** 四旋翼、开源、科研导向、可靠。不追求替代 PX4 的全机型覆盖,而是提供一个结构小、接口清晰、算法可插拔、可验证性强的参考平台。

**范围边界。**

- 硬件:仅 Pixhawk 6X(FMUv6X)。
- 机型:仅多旋翼(四旋翼优先)。
- DroneCAN:仅 ESC。
- 不做:固定翼、VTOL、其他 DroneCAN 外设、SIH(暂缓)。

**兼容策略。** 对外声明为 PX4 autopilot(HEARTBEAT 中 autopilot 字段为 MAV\_AUTOPILOT\_PX4,并使用 PX4 的 custom\_mode 编码),这样 QGC 会按 PX4 的界面和流程工作,参数名尽量沿用 PX4(MC\_*、EKF2\_*、COM\_*、CAL\_* 等)。代价是需要持续对照 PX4 的约定;收益是几乎零迁移成本。具体编码以 PX4 源码中的 px4\_custom\_mode.h 与 MAVLink 官方 message 定义为准。

## 2. 贯穿各阶段的原则

1. **先闭环,后扩展。** 每个阶段都以「可在台架上验收」为完成标准,不接受「代码写完但没验证」。
2. **安全先于功能。** 解锁检查与最小 failsafe 在 P0 就要有,不能留到后面。
3. **接口可插拔。** 估计器、控制器、混控定义为 trait,输入输出类型固定(坐标系 NED/FRD、单位 SI 用类型表达),研究者只需实现 trait。
4. **基线控制器作为安全后备。** 实验性控制器越界或失效时自动回退到基线控制器。
5. **可观测性。** 无 SWD 探针时,日志和遥测是主要调试手段;控制环时序(周期、抖动、超时)从第一天起就记录。
6. **与 PX4 对照验证。** 同一份传感器日志回放到 Rust 版与 PX4,比较估计与控制输出,作为回归测试。

## 3. P0:最小可飞闭环与基础兼容

**目标。** 传感器 → 估计 → 姿态/速率控制 → 电机输出 → QGC 看到遥测、能读写参数、能解锁和切换模式。完成 P0 即具备台架调试和系绳首飞的条件。

### 3.1 工作项

**A. 运行时与驱动层(embassy-stm32)**

- 板级初始化、时钟、中断优先级规划;控制环使用固定周期任务(高优先级执行器),通信与日志使用低优先级任务。
- 仅驱动 Pixhawk 6X Rev 3 实际检测到的传感器(IMU、气压计、磁力计等)与所需外设(UART、CAN、PWM/DShot、SDMMC 后续)。
- DroneCAN:仅 ESC 控制与反馈。
- 控制环时序监控:记录实际周期、最大抖动、超时次数。

**B. 估计与控制(P0 取最小集)**

- 姿态估计:互补滤波或简单 EKF 先行,保证姿态模式可用;位置估计待 EKF2 Rust 移植成熟后接入(见 P1)。
- 控制结构:角速率环 + 姿态环 + 混控;参数沿用 MC\_ROLLRATE\_P 等 PX4 命名。
- 飞行模式:Stabilized、Acro(以及可选 Altitude),先不开放位置类模式。
- 控制器与混控以 trait 暴露,附一个基线实现。

**C. 安全与解锁逻辑**

- 解锁前检查:传感器健康、参数合法、姿态有效、遥控有效、电池电压。
- 最小 failsafe:遥控丢失、地面站丢失(可配置)、电池低压、估计器失效、控制环超时。每项有明确状态机与动作(例如降落或锁定)。
- 电机输出保护:上锁时强制最小/零输出,软件看门狗与硬件看门狗启用。

**D. MAVLink 基础(v2)**

- 串口/USB CDC 链路,心跳 1 Hz;系统与组件 ID 约定。
- 必需消息:HEARTBEAT、SYS\_STATUS、ATTITUDE、ATTITUDE\_QUATERNION、LOCAL\_POSITION\_NED、GLOBAL\_POSITION\_INT(无定位时给无效值并标注)、GPS\_RAW\_INT、BATTERY\_STATUS、RC\_CHANNELS、SERVO\_OUTPUT\_RAW、HIGHRES\_IMU、STATUSTEXT、AUTOPILOT\_VERSION、PROTOCOL\_VERSION。
- 命令:COMMAND\_LONG / COMMAND\_ACK,至少实现 ARM/DISARM(MAV\_CMD\_COMPONENT\_ARM\_DISARM)、设置模式(MAV\_CMD\_DO\_SET\_MODE)、REQUEST\_MESSAGE、SET\_MESSAGE\_INTERVAL。
- 模式上报:HEARTBEAT 的 base\_mode 置 CUSTOM\_MODE\_ENABLED,custom\_mode 按 PX4 的 main\_mode/sub\_mode 编码。

**E. 参数协议与持久化**

- 实现 PARAM\_REQUEST\_LIST、PARAM\_REQUEST\_READ、PARAM\_SET、PARAM\_VALUE;参数表带类型、范围、默认值。
- QGC 连接时会拉取整表,需要保证分包节奏稳定、不丢包、不阻塞控制环。
- 持久化:写入 flash 或板载 FRAM(以 Pixhawk 6X 实际硬件为准);写入过程不得影响控制环,并带校验与回退默认值机制。

**F. 遥控输入**

- SBUS 或 CRSF 之一先行;失控检测与通道映射沿用 RC\_MAP\_\* 参数。

### 3.2 验收标准

- QGC 能连接,正确显示机型为 PX4 多旋翼、飞行模式、姿态、电池、传感器状态。
- 参数整表加载无丢失;在 QGC 中修改并持久化后,重启仍有效。
- 解锁/上锁、模式切换在 QGC 与遥控两侧行为一致;解锁检查失败时 QGC 能看到 STATUSTEXT 原因。
- 拆桨台架:遥控输入到各电机输出的映射正确;各 failsafe 逐项触发并验证动作。
- 控制环连续运行 ≥ 1 小时:无超时、抖动在设定阈值内。
- 系绳或防护笼首飞(Stabilized):能悬停且无异常振荡。

### 3.3 风险

- QGC 对 PX4 有隐含假设(参数名、STATUSTEXT 文本、消息频率),缺项时界面会灰掉或提示错误,需要边接边调。
- 没有 SWD 探针时底层问题排查困难,建议尽早配备探针。

## 4. P1:日志、位置估计与任务

**目标。** 具备科研所需的可复现日志,接入 EKF2 Rust 版实现位置类模式,支持基本任务。

### 4.1 工作项

**A. ULog 日志**

- 按 ULog 格式写入:文件头、消息定义、订阅、数据、日志文本、参数快照(写入启动时参数)。
- 存储:SD 卡(SDMMC + FAT 文件系统),写入走独立低优先级任务与缓冲,保证控制环不受影响;缓冲溢出要记录丢失计数。
- 记录内容:传感器原始数据、估计状态与协方差(科研关键)、控制器内部状态(参考值、误差、积分项)、电机输出、模式与 failsafe 事件、环路时序。
- 日志下载:支持 MAVLink 日志协议(LOG\_REQUEST\_LIST、LOG\_REQUEST\_DATA、LOG\_ENTRY、LOG\_DATA、LOG\_ERASE),使 QGC 能列出和下载;并视情况支持 MAVLink FTP。
- 兼容目标:PlotJuggler、pyulog、Flight Review 可直接打开。

**B. EKF2 Rust 接入**

- 将 EKF2 Rust 移植版(IMU、GPS、雷达高度计、气压计、磁力计)接入,沿用 EKF2\_\* 参数。
- 提供不依赖 GPS 的导航解输出接口(与 EKF2 主输出并存)。
- 估计器通过 trait 接入,可替换为其他融合算法。
- 回放验证:同一份日志同时喂 Rust 版与 PX4 EKF2,对比状态与创新量,设定可接受偏差。

**C. 位置类飞行模式**

- Altitude、Position(基于估计器输出),Hold。
- 估计器失效时的降级策略:Position → Altitude → 手动/降落,降级过程有明确事件与提示。

**D. 任务协议与自动模式**

- 实现 MISSION\_COUNT、MISSION\_REQUEST\_INT、MISSION\_ITEM\_INT、MISSION\_ACK、MISSION\_CLEAR\_ALL、MISSION\_CURRENT、MISSION\_ITEM\_REACHED。
- 支持命令:NAV\_TAKEOFF、NAV\_WAYPOINT、NAV\_RETURN\_TO\_LAUNCH、NAV\_LAND。
- Home 位置设置与上报;返航(RTL)与自动降落。
- 路径跟踪控制器作为可替换模块(trait)。

### 4.2 验收标准

- 日志可在 QGC 中列出并下载,且能被 Flight Review 与 pyulog 正确解析;连续记录 ≥ 30 分钟无丢帧(或丢帧被明确计数)。
- 回放对比:Rust 版与 PX4 EKF2 在同一日志上的位置、姿态、速度估计偏差在预先设定的阈值内。
- 台架 + 手持测试:估计器在传感器掉线、GPS 丢失时按设计降级,并产生事件。
- 任务:QGC 上传、下载、清除任务往返一致;在 SITL 或系绳/限高条件下完成起飞—航点—返航—降落。

### 4.3 风险

- ULog 写入与 SD 卡延迟抖动是常见的实时性隐患,需要实测写入最坏延迟。
- 位置类模式首飞必须有手动接管通道与保护(限高、限距、防护笼或开阔场地)。

## 5. P2:校准流程与参数元数据

**目标。** 让 QGC 的传感器校准向导与参数界面完整可用,降低使用门槛。

### 5.1 工作项

**A. 传感器校准(QGC 向导兼容)**

- 处理 MAV\_CMD\_PREFLIGHT\_CALIBRATION 命令(陀螺、加计、磁力计、水平、气压/空速等按需)。
- QGC 向导依赖飞控发送特定格式的 STATUSTEXT(例如带 \[cal\] 前缀的进度、姿态提示、完成与失败消息),需对照 PX4 实际输出的文本逐条实现。
- 校准结果写入 CAL\_\* 参数,并在下次启动时应用;校准失败要给出明确原因。
- 对于磁力计校准,结合你已有的磁干扰分析经验,可增加校准质量评估(拟合残差、覆盖度)。

**B. 遥控校准与模式映射**

- 实现 QGC 遥控校准页所需参数(RC\_MAP\_\*、RC{n}\_MIN/MAX/TRIM、RC{n}\_REV)。
- 飞行模式通道映射(如 COM\_FLTMODE\*)与失控动作参数。

**C. 参数元数据**

- 让 QGC 显示参数的说明、单位、范围、枚举:通过 MAVLink 组件元数据协议(COMPONENT\_METADATA)指向参数描述文件,并经 MAVLink FTP 提供。
- 参数表与元数据由同一份源文件生成,避免两处不一致。

**D. 地理围栏与 Rally(可选)**

- 基础地理围栏(圆形、多边形)和触发动作,作为科研飞行的安全边界。

### 5.2 验收标准

- QGC 的加计、陀螺、磁力计校准向导能完整走完,提示文本与进度条正常,结果持久化并在重启后生效。
- 遥控校准页可完成,模式通道映射正确。
- QGC 参数页显示说明、单位、范围,编辑越界值被拒绝或提示。
- 校准后的传感器偏置/比例因子经日志验证(静置残差在预期范围)。

### 5.3 风险

- STATUSTEXT 文本与流程细节随 QGC 版本变化,需固定一个测试用的 QGC 版本并记录。
- 元数据协议实现较繁琐,可先用文件方式提供,再补完整协议支持。

## 6. P3:固件更新与高级配置

**目标。** 降低日常使用与分发成本,使第三方研究者能在不接探针的情况下刷写和配置。

### 6.1 工作项

**A. 固件更新**

- 保留 PX4 兼容的 bootloader,使 QGC 能通过其「自定义固件」功能直接刷写。
- 构建流程生成 QGC 可识别的固件包(.px4,含 board\_id 与压缩镜像),CI 中自动产出。
- 参数区与日志区布局在升级时保持兼容,避免升级丢参数。
- 若无探针,务必保证 bootloader 永不被覆盖,并提供从 USB 进入 bootloader 的可靠方式。

**B. 载具配置页面**

- 机型/框架选择、电机顺序与旋向、执行器配置:先通过参数实现,再逐步满足 QGC 的 Actuators 配置界面所需的参数与接口。
- 电机测试命令(MAV\_CMD\_DO\_MOTOR\_TEST),支持拆桨台架验证。

**C. 科研扩展接口**

- Offboard 控制:接受 SET\_POSITION\_TARGET\_LOCAL\_NED、SET\_ATTITUDE\_TARGET 等,并带超时保护。
- 实验管理:在线切换控制器/估计器、受保护的参数在线修改、扰动注入,越界自动回退基线控制器。
- 文档与示例:「如何新增一个控制器」「如何接入新估计器」「如何回放日志对比」三篇教程,配最小示例工程与 CI 测试。

### 6.2 验收标准

- 全新板子仅凭 USB 与 QGC 即可刷入固件并完成首次配置,参数在升级后保留。
- 电机测试命令在拆桨台架上可用,并有超时与上锁保护。
- Offboard 通道中断时,飞控在设定时间内退出并执行 failsafe。
- 按教程由外部人员新增一个控制器并成功回放与台架验证(以此检验接口设计是否真的可用)。

### 6.3 风险

- bootloader 与固件包格式一旦与 QGC 不匹配,会出现无法刷写的情况,需要早期用空固件验证流程。
- 执行器配置界面对 PX4 新版控制分配有较多假设,工作量可能超预期,可降级为参数配置。

## 7. 里程碑与顺序建议

| 阶段 | 里程碑 | 完成标志 |
| --- | --- | --- |
| P0 | M0.1 驱动与环路时序 | 传感器数据稳定、环路抖动达标 |
| P0 | M0.2 MAVLink 与参数 | QGC 连接、整表参数读写持久化 |
| P0 | M0.3 控制与 failsafe | 台架映射与 failsafe 全通过 |
| P0 | M0.4 系绳首飞 | Stabilized 悬停 |
| P1 | M1.1 ULog 与下载 | Flight Review 可解析 |
| P1 | M1.2 EKF2 Rust 接入与回放对比 | 与 PX4 偏差达标 |
| P1 | M1.3 位置模式与任务 | 自动任务完成 |
| P2 | M2.1 校准向导 | 三项传感器校准走通 |
| P2 | M2.2 参数元数据与遥控校准 | QGC 参数页完整 |
| P3 | M3.1 固件更新 | 仅 USB 刷写 |
| P3 | M3.2 Offboard 与实验接口 | 教程可复现 |

**顺序说明。** P0 内部先做 M0.1 到 M0.2,让 QGC 早点连上,因为 QGC 的兼容问题越早暴露越便宜。日志(M1.1)尽量提前到 P0 后期开始,因为它是后续所有调试和验证的基础。

## 8. 总体风险与对策

- **范围蔓延。** 飞控、EKF2、DroneCAN、日志、MAVLink 并行推进易失控。对策:严格按里程碑串行验收,P0 未完成不启动 P2/P3。
- **缺少探针。** USB-only 调试成本高。对策:尽早配备 SWD 探针;同时把日志与遥测做好。
- **飞行安全。** 对策:拆桨台架 → 系绳 → 防护笼/开阔场 → 逐步放开模式;每次新增模式或控制器都先走回放与台架。
- **QGC 版本漂移。** 对策:固定测试版本,记录兼容矩阵。
- **开源后的可维护性。** 对策:自动化测试(回放对比、MAVLink 往返测试、参数一致性检查)进 CI;文档与示例与代码同步更新。
