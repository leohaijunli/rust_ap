## 范围与证据

- GNSS 独立 110 ms 延迟缓冲、位置/速度/高度序贯更新、初始 10 s 健康等待、短期恢复、原点与高度偏置；共享核心不接收 GNSS 类型，GNSS 仅通过明确的控制阶段扩展接入。
- 雷达独立 5 ms 缓冲、倾角/量程/质量滞回、stuck、默认 3 m fog 中值检查、运动一致性、条件高度/地形融合及相关协方差。
- 原版 WMM 表与 EKF-GSF 预测/更新公式已移植。WMM 30 个边界/内部点与 C++ 的 f32 输出逐位一致。当前数值门不声称 GSF 紧急偏航重置或所有机动分支已资格通过；重置专项归 E5-H。
- Auto GNSS 策略、默认 in-air 配置；未支持的 DeadReckoning 参数值显式拒绝。没有 GNSS ground-drift、双天线航向、fog 硬件模型、板载参数桥或真实五传感器输入资格。

## 历史失败与修复

1. 默认 `EKF2_RNG_FOG` 实为 3 m，早期独立 sensor 测试只覆盖 disabled 配置；随后加入真实默认中值遮挡/恢复检查，不以旧测试冒充默认覆盖。
2. GNSS 初始化高度后 nominal posD 可暂时缓存旧值；雷达应读当前 global altitude。修复后完整状态门通过。
3. 首次 range-height 更新产生 f32 位差，后来在 100 m 附近的 HAGL 相消越过一个 ULP，NIS 超限。根因为 PX4 Matrix 标量除法是乘倒数；Rust 匹配其运算次序后前三场景 NIS 通过，门限未放宽。
4. 中断/质量场景在恰好 1 s 时只差 dead-reckoning bit；`isRecent` 是严格 `last + interval > now`，不能用 `!isTimedOut` 替代。按原版修复、边界用例与完整复验通过。
5. exact `0.7071f` 被 Clippy 当成近似数学常量；保留原版 bit pattern，不替换成 `1/sqrt(2)`。GSF 索引 lint 用等价显式对称赋值修复。
6. 一个 WSL 启动命令超时、普通重试成功；Windows Python 缺少 pyulog 的真实失败保留，改用已有 WSL 环境后全套通过，不跳过测试或新增环境。
