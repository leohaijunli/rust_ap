## Qt错误为何看起来像权限问题

核对与实际库版本一致的[Qt SerialPort v6.11.1源码](https://raw.githubusercontent.com/qt/qtserialport/v6.11.1/src/serialport/qserialport_unix.cpp)：

- 75–116行按固定顺序找锁目录；无已有锁且前几个目录不可写/不存在时，先选择`/tmp`，然后才考虑`/var/tmp`。
- 目录“可写”检查不能保证配额下能创建文件。选好路径后不会因创建失败自动换到下一目录。
- 307–322行中`QLockFile::tryLock()`失败统一报`Permission error while locking the device`，该分支发生在tty打开之前。

现有主机证据与`/tmp/LCK..ttyACM0`创建受EDQUOT阻塞高度一致；用户后续清理`/tmp`后刷回PX4成功，进一步支持配额导致锁创建失败的判断。**未直接trace当次QGC syscall，复测成功依据为用户报告，而非agent串口测试。** 单设`TMPDIR=/var/tmp`不能可靠解决固定候选列表优先选择`/tmp`的问题。
