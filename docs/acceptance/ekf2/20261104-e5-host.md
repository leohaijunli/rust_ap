# E5-H：复位、故障与恢复

**本地软件门通过；CI 正确性由工程师确认，本轮不重复核对。** 固定 PX4 v1.17.0 `d6f12ad1c4f70ad3230afd7d86e971421e02fef4`；四个固定 C++ 场景的复位计数、状态/协方差、NIS 与事件逐项对拍通过。未刷写，不是 8 kHz 板载时序、真实传感器故障或飞行资格。

- 四元数最大差范数分别为 `1.22e-7`、`0`、`7.21e-10`、`7.07e-9`；时间、control/fault、复位时刻与逐项计数完全相等，NIS 表按 `1e-6` 绝对 / `1e-4` 相对通过。
- 覆盖：GNSS 超时重置与恢复、协方差去相关、速度/高度/地形/偏航复位传播、GSF 偏航对准、气压参考高度重初始化、坏垂直加速度检测/抑制/恢复。
- `vertical_clipping` 是刻意注入的 30 m/s² 加计误差：`bad_acc_vertical` 于 `12.1425 s` 置位，期间按 PX4 语义暂停加计零偏学习并反复重置高度，`24.8825 s` 解除（含 10 s 持续期），最终在 `26.8925 s` 恢复地形参考。C++ 与 Rust 的 153/155 次复位逐次一致。该场景只证明故障路径等价，不代表真实飞行中允许该量级的加计错误。
- 黄金输入、真值、状态/协方差、NIS、复位 sidecar 与来源/二进制 hash 固定在 `tests/data/ekf2/resets_{gnss_reset,baro_reset,gsf_yaw,vertical_clipping}/`，不可覆盖；容差沿用 E1 既定值，未放宽。

## 历史失败

1. `baro_reset` 首次对拍失败：Rust 用字面 `0.1f` 做传感器低通，原版是 `0.01/(0.09+0.01)`，差一个 ULP 后逐步放大。改为同源表达式，未改数据或容差。
2. `vertical_clipping` 首次对拍在 `12.20 s` 仅 control bit 20（地面效应）不同：fixture 使 HAGL 越过自动地面效应阈值，Rust 尚未移植 `updateGroundEffect` 与气压创新死区。按固定顺序补齐后仍不通过——`12.16 s` 起加计零偏 Y 偏离，原因是 `bad_acc_vertical` 未纳入零偏抑制条件；补齐后四场景全通过。
3. 工具侧：通用黄金检查器最初把该 fixture 的预期故障位当失败；改为只放行显式配置的 bit 10/11，默认无故障及其他位仍严格拒绝，并加回归用例。首次 5 m/s² 的错误注入未触发故障门，保留为失败记录后改用 30 m/s²，事件门与数值容差未放宽。

## 重现

```sh
python3 tools/golden_cpp/build.py --profile gnss_range --output target/ekf2-host-resets
python3 tools/golden_cpp/build.py --profile gnss_range --fixture baro_reset --output target/ekf2-host-gnss-range-baro-reset
python3 tools/golden_cpp/build.py --profile gnss_range --fixture gsf_yaw --output target/ekf2-host-gnss-range-gsf-yaw
cargo build --release --example ekf2_input --target x86_64-unknown-linux-gnu --locked
for case in gnss_reset baro_reset gsf_yaw vertical_clipping; do
  python3 tools/check_ekf2_resets.py --case "$case" --rust target/x86_64-unknown-linux-gnu/release/examples/ekf2_input
done
```

报告位于忽略的 `target/ekf2-host-resets/check-*/report.json`。CI 在 `.github/workflows/p1.yml` 的 "Qualify EKF resets and fault recovery" 步骤执行同一组场景。
