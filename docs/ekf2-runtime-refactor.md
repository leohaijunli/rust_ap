# EKF 运行时重构与优化计划（方案 A1）

更新：2026-11-05。工程师已要求执行本计划，以新代码重测。
实施状态见 [TODO](../TODO.md)，必要检查与硬件依赖以 [主计划](../plan.md) 为准。

## 目标与约束

- `Runtime<F: NavFilter>` 每个实例只持有一个主算法；产品使用主 Runtime 和独立无 GNSS Runtime。
- 保留 `NavFilter` 现有七个方法的签名；`GnssEkf`、`NoGnssEkf`、`Mahony` 实现同一调度契约。
- 驱动通过产品类型别名调用；新增算法的数学实现留在自己的模块，粒子滤波等不依赖 EKF 的标量更新或协方差实现。
- IMU 高频传播、量测事件入口、1 kHz 姿态发布与延迟融合分开；滤波器由单一任务独占，有界队列传递输入，轻量快照传递输出。
- 量测到达即验证、入队；状态和协方差对齐到允许融合的延迟时刻后修正。保留确定的融合顺序、输出预测器和复位传播。
- 保持纯 Rust/no_std/Embassy、固定容量、原 PX4 bootloader、`0x08020000` 入口与 QGC 恢复能力。
- 真实 mag/range 融合需要相应驱动、标定和硬件；软件入口通过与实物融合通过分别记录。

## 前置护栏（阶段 0）

1. 保留现有固定 PX4 v1.17.0 黄金输入、容差和历史失败记录；用新实现回放，不覆盖旧黄金数据。
2. 补齐运行中仍读取默认值的参数：`EKF2_NOAID_TOUT`、`EKF2_BARO_CTRL`、`EKF2_GND_*`、`EKF2_MAG_CHK_*`、`EKF2_MAG_ACCLIM`。唯一参数快照在明确 apply/reconfigure 边界生效。
3. 增加分路径计时：共享输入、主算法、独立算法、姿态发布、完整标准快照。记录样本数、max 和有明确精度的 p99。
4. 单次超时保留诊断并继续计算；连续超时才降级，恢复探测具有明确退出条件。
5. 核对构造/重配置的大对象、ARM 调用栈和配置失败传播；历史 reconfigure 参数异常由新代码实测闭环。

当前普通 IMU 日志是抽取后的 `sensor_accel/gyro`，不能据此恢复等价的积分输入。
真实 ULog 回放应使用包含完整积分字段的 `vehicle_imu`，或满足固定输入契约的 `sensor_combined`；事件回放还须保留量测时间、到达时间、顺序及配置变化。

## 阶段 1：泛型 Runtime 与算法接口

### 实施内容

- 建立单算法 `Runtime<F>`，包含监督状态和热运行 Mahony 回退。
- 产品侧定义 `ProductRuntime`、`IndependentRuntime`、`MahonyRuntime`，采用 A1 双实例组合。
- `estimator-mahony` feature 仅切换产品类型别名，用于编译验证同一驱动任务可搭配 Mahony；普通固件默认仍选主 EKF。
- 三个现有算法实现 `NavFilter`；`push_imu` 负责传播/积累，`push_measurement` 接收量测，`step` 服务待处理的延迟融合周期。
- Runtime 提供 `ingest_imu`、`apply_measurement`、`attitude_at`、`maintain`，保留旧 `update` 回放适配入口。
- 产品参数映射与标准输出适配放在边界模块，通用监督逻辑不读取 EKF 内部状态。
- 移除一次性全局原子探针与重复构造诊断，使用实例健康和配置错误结果；减少大对象跨异步调用边界的按值传递。
- 大型 MCU 实例通过 `Runtime::with_initializer` 绑定产品层原地初始化函数，重配置/恢复直接写现有静态存储。普通 `Runtime::new` 保留 `NavFilter::new` 默认构造；初始化函数只用于存储生命周期，不参与逐样本算法分派。

### 主要文件

`src/core/estimator/{mod,runtime,runtime_params,product,mahony,imu_ekf,gnss,no_gnss}.rs`

### 验收

- `Runtime<GnssEkf>` 与 `Runtime<Mahony>` 均可构建运行；更换产品别名可完成相同任务循环。
- 驱动任务中不出现具体 EKF 类型名，具体选择集中于产品别名。
- 旧入口和新分步入口以相同输入验证状态、输出与失败传播；保存配置失败及重新配置成功的证据。
- 独立实例不接受 GNSS 修正，主实例的坏 GNSS 不改变独立实例状态或协方差。

## 阶段 2：1 kHz 姿态与量测事件

### 实施内容

- 独立 1 ms 发布任务读取轻量姿态快照；完整 EKF 更新、日志编码和大快照构造留在较低优先级路径。
- 使用绝对释放时刻，记录迟到、遗漏周期、重复样本及样本年龄；发布时间与真实样本时间分开。
- 滤波器保持单一可变所有者。传感器生产者通过固定容量队列提交事件，队列溢出与陈旧/重复/非法观测显式计数。
- baro/GNSS 从新样本发布点触发；mag/range 使用相同统一入口，独立时间戳不互相伪造。
- Range 的质量未知值 `-1`、实际量程和安装配置保持真实语义，量程元数据随延迟观测传播。
- 保留倾角/偏航对准、质量门、aid 超时、标量序贯顺序、复位计数和延迟输出校正。
- 1 kHz 是内部姿态发布节拍；日志、USB 与 TELEM1 仍按各自预算取快照。

### 主要文件

`src/drivers/{estimator,barometer,dronecan_can}.rs`、`src/main.rs`、
`src/core/estimator/{baro_mag,range_fusion,range_sensor,standard_output,publication_reset}.rs`

### 验收

- 发布路径不执行完整协方差预测/融合；新固件记录 1 kHz 实际周期、最大延迟及数据年龄。
- 同一观测至多消费一次，尚未满足时间条件的观测等待，过期/越界输入有明确处理。
- 主算法切到 Mahony 后同一任务代码可运行。
- 软件验证 mag/range 融合与缺失/拒绝路径；硬件具备后验证无 GNSS 的磁航向约束，并区分磁北/真北参考。

## 阶段 3：共享预处理、恢复与时间健壮性

### 实施内容

- 一份 IMU 解码/坐标转换/时间检查及 8 kHz→约 1 kHz 积分，供所有实例与 Mahony 回退使用。
- 保留旋转复合、速度补偿、独立积分时长和 clipping；偏置修正、状态、协方差及融合历史由各实例独立持有。
- 各 EKF 自行管理其低频延迟预测窗口。共享前端减少高频重复工作，独立 EKF 的状态和协方差计算仍计入额外成本。
- Runtime 监督模式为 Running、Degraded、SoftResetting、Fatal：丢样/陈旧/超时进入恢复流程；数值或配置失败要求重新配置。
- 恢复时处理 IMU 序列重同步、积压事件、滤波历史、输出有效性和复位计数；保留历史故障原因，避免反复切换。
- Deadline 连续计数只按完整计算周期更新，轻量 IMU 输入不能清除重步超时计数。
- 工程师追加要求：完整 EKF 重步预算放宽为 2000 µs，1 kHz 姿态发布仍按 1000 µs 节拍；三次连续重步超时才降级。
- 延迟校验按时间跨度计算：实际 IMU 历史跨度覆盖启用 aid 的最大延迟及余量，并检查固定容量上限。
- 长窗口比较 IMU `Σdt` 与 TIM2 时间差，记录 ppm 偏差。`1 ± 1e-4` 作为核对目标，先核实传感器量化、实际 ODR 和时钟语义，再决定积分时基调整。
- DWT 原始周期包含抢占；算法执行时间与端到端响应时间分别报告，扣除 IRQ 时间须有可核对的计数依据。

### 主要文件

`src/core/estimator/{runtime,imu_downsampler,output_predictor,timing,runtime_params}.rs`、
`src/drivers/{estimator,imu}.rs`、`src/diagnostics.rs`

### 验收

- 单次超时后继续更新；连续超时降级、健康探测后恢复，历史 miss 计数保留。
- IMU 丢样后重新同步，不因旧序列号持续拒绝所有新输入；过期姿态撤销有效性。
- 错误延迟配置在启用前拒绝。
- 新固件分别记录共享输入、主算法、独立算法、发布及联合负载的耗时、CPU、队列与栈余量。

## 阶段 4：算法扩展约定与 MCU 效率优化

工程师最新收敛范围为 **4.0 FPU 配置与基线**：保持 hard-float target，显式 `target-cpu=cortex-m7`、release `opt-level=3`/LTO；核对 FPU 启动及硬件开方，保存三路径 DWT。当前 Rust 1.99.1 的 `no_std` 实测不支持固有 `f32::sqrt()`（E0599），需使用等价的目标端硬件入口。4.1 稀疏化、4.2 小角度等继续后置。

**进入条件：阶段 1–3 相关行为与实时性验证通过。每次只引入一类优化并复验受影响结果。**

### 实施内容

1. **扩展约定**：记录新算法实现 `NavFilter`、参数映射、编译期产品别名及可用输出字段的方法。PF 等算法自行解释量测，不复用 EKF 专用更新公式。
2. **稀疏 H**：对已知结构跳过零项，先定位真实热点；声明位级保持的路径须逐位核对。
3. **小角度与归一化**：明确近似适用范围、误差界和回退路径，再评估泰勒展开与牛顿步骤。
4. **协方差与内存**：减少临时矩阵、按需原地/三角存储和大对象复制，核对依赖的更新顺序与对称性。
5. **Cortex-M7 FPU**：核对实际编译目标和反汇编中的浮点/平方根指令；硬浮点 ABI 本身不证明所有 `libm` 路径都已硬件化。需要改目标特性时同步复验数值、代码大小和执行时间。
6. **MCU 能力边界**：STM32H753 没有 CORDIC/FMAC，也没有浮点 NEON；M7 DSP 的定点打包指令仅在存在合适的数据路径和实测收益时采用。保持板上纯 Rust，不以 CMSIS C FFI 替代数学核心。
7. **热数据布局**：按实测评估 DTCM/现有 SRAM 的热点放置和访问成本；DMA 缓冲保持在相应控制器可访问的区域。
8. **可选数值改进**：当前通用量测更新已有 Joseph 形式，先核对现有实现。局部重力或其他公式变化单独立项，具备参考真值后再用 f64 影子、NIS/NEES 判断。

### 验收

- 所有优化有修改前后可比的 MCU 耗时、资源和数值结果。
- 声称 bit-exact 的修改要求结果完全一致；改变数值路径/时序的修改使用测试前确定的容差，不以放宽阈值掩盖错误。
- 保留完整状态/协方差、创新与拒绝/复位事件检查；无需为本阶段默认启动全量覆盖率、SIMD、PGO 或大规模蒙特卡洛。
