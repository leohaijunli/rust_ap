- 6 项按钮/蜂鸣用例：消抖、上电按住、长按不落入短按、调度延迟仍按实际时间分类、LED 模式策略、蜂鸣包络不追赶过期脉冲。
- 对未修改的 PX4 v1.17.0 `protocol.h` 编译运行 `tools/px4io_reference.cpp`（GCC 4.9.2、C++11），与 Rust 请求/回复逐字节比较；原始输出见 [reference.txt](20261104-reference.txt)。tag 对象 `a5eb12d2…` 已核对指向固定 commit `d6f12ad1c4f70ad3230afd7d86e971421e02fef4`。
- host / 普通 H7 target Clippy `-D warnings`、相关格式检查和 release/打包/分区/向量/ELF/bin/PX4 一致性通过。未跑全 feature 或重做无关 EKF 数值测试。

## 修复与限制

- 早期包 `473ffd4797e692f3` 虽通过编译/布局，但错误地直接驱动 PD10、将 PF9 当作 MCU 开漏；PX4 源码审查后已撤回，保留为 `.px4.withdrawn-473ffd4797e692f3`，不可烧录。
- 当前 PD10 保持输入，IO 安全灯没有 logger 覆盖；`LOGGER_SWITCH.requested_on` 只是模式请求，不是实际发光证明。GPS1 I²C 灯和左右小灯尚未识别。
- 已修复首次控制台 `?` 返回类型错误、新 Clippy chunk API 要求，以及原按样本数计算长按的调度延迟问题。host 参考编译器不支持 C++17，改用所需的 C++11；未修改上游头文件。
- 外层 async 预算不能抢占同步 SD/HAL 或证明 DMA 取消的物理时限；实际延迟、响应与错误恢复待 H-12。
- 尚待工程师拆桨验证：`!px4io` 的协议/CRC/配置与 PWM=0、按钮空闲/按下电平、IO 长按锁存/ACK、短按 start/stop 与长按无动作、蜂鸣、生成日志独立解析。IO-R0 还需 SWD/原 IO 备份和恢复条件。软件门不放行非零输出或完整 IO 替换。
