## 栈实测与解释

```text
STACK bytes=65536 untouched_bytes=5040 touched_bytes=60496
      min_msp=240789a0 guard_ok=true
EKF2_RUNTIME requested=false epoch=1 active=false
```

- `untouched_bytes` 是启动以来栈涂色保留下来的区域，不是瞬时 SP 到底部的距离。曾经构造大对象后即使函数返回，历史水位不会恢复；`min_msp` 只是抽样，不能保证捕获峰值。
- Cortex-M 当前共享 MSP；线程启动、函数临时量及中断嵌套均占同一 64 KiB 栈。Embassy future 常驻静态区不代表构造 future/按值传递大对象也不消耗调用栈。
- ARM 反汇编确认旧包 estimator poll 入口实际预留 **149448 B**（含 push/vpush），超过整个 64 KiB 栈；进入函数即预留，与 `EST_EN=0` 无关。host `Runtime` 大小 39176 B 只是线索，不能代替 ARM 证据。涂色只反映实际写入的位置，不能证明所有 SP 下探安全。
- `guard_ok=true` 与无有效 fault 只说明这次没检测到越界，不能满足原 ≥32 KiB 余量门。因此未发送 `!ekf2 start`，未宣称 EKF 输出或周期通过。

## 损坏定性（软件，非硬件）

- 损坏值是规整 IEEE 浮点（`230.0`=`0x43660000`、`290.0`=`0x43910000`），不是 RAM 位翻转的随机位型；失败字段随编译布局漂移（改代码即从字段 7 移到字段 8）；同一块板长时间运行 IMU/SD/CAN/USB 全部健康且 `guard_ok=true`。**结论：软件越界写，非硬件故障。**
- 协方差循环已排除：`STATE_COUNT=24`（误差态）、`NOMINAL_STATE_COUNT=25`（名义态含 4 分量四元数），`Covariance=[[f32;24];24]`，全部循环索引 0..=23 在界内；gain/ph 均为 24 维。这是 PX4 标准维度约定，不是索引错误。
- 已确认的损坏窗口：reconfigure_staged 各构造步骤（含逐字段比对通过）之后、`configure_output` 的 `buffer_length` 读取之前；即 `initial_horizontal_noise` + `enable_gnss` 窗口。嫌疑集中在 `GnssAids`（约 8 KB，栈上构造后移入静态 `Option`）或 Rust 字段重排后相邻字段写入越界。
- 排除项：DMA 目标均为静态缓冲；D-cache 关闭；Watch/队列写入均在临界区内；`Runtime` 为 task 独占 `&mut`，无并发写者；TIM7(IMU) 可抢占 TIM5(EKF) 但只写自己的静态。
- 影响边界：EKF `update()` 数学路径 14 万+样本无损坏（栈余量 42 KiB、期限 0 miss、IMU 零错误）；损坏仅在 reconfigure 窗口出现，因此 **EKF2 不可用，Mahony 回退正常**，遥测/日志不受影响。

## 其他失败已保留

- runtime 合成用例最初在 boot t=125 µs 输入 dt=128 µs，合法性拒绝，弱断言仅看到 fallback；改用真实可成立的时间基点并要求 EKF update>0，独立气压/无伪磁用例通过。
- QGC JSON 初次在 Windows 写为 CRLF，CRC 与 UTF-8 字节不符；生成器固定 LF。大浮点边界的字符串比较改为解析 f32 后逐位比较，4 项 metadata 测试通过。
- PowerShell 单元素参数被解包成 String，`py` 误入交互模式；固定为 `string[]` 后实际 build/打包及 upload `-DryRun` 通过。RustRover 日志确认原 `/bin/bash` 路径在 Windows 不存在，run 配置改 PowerShell，Ubuntu 入口保留。
