# 日志 Dropout 缓解与极端优化备选

更新：2026-11-07。范围：SD 日志 dropout 的缓解层级。第 1–3 层是当前执行路径；第 4 层是结构化兜底，仅在 1–3 层与 H-04 卡选型之后仍不达标时评估。工程师同意先执行 1–3，第 4 层暂不实施。

## 实测基线

2026-11-06，固件 `eb0d589438e0a6dc`，65 s 正常路径采集（`16.ulg`，2.42 MB）：

| 指标 | 数值 |
| --- | --- |
| dropout 次数 / 总丢失 | 41 / 196.7 ms（占时间线 0.31%） |
| 单次时长 | 中位数 2 µs；最长 65.5 ms（一个周期量级，疑似卡级停顿） |
| 固件队列丢弃 | normal 9 条 / event 0（约 5.6 万条记录，≈0.016%） |
| 队列高水位 | 4256 B / 168 KiB（2.5%） |
| 产生速率 | ≈37.6 kB/s（200 Hz IMU + 估计器 12 topic + 400 Hz raw_command 等） |

结论：队列吸收能力充足，丢失来自写入端瞬时停顿与产生侧突发叠加；`dronecan_raw_command`（400 Hz 全零命令，纯诊断）贡献了无信息量带宽。

## 缓解层级

### 第 1 层：砍掉 `dronecan_raw_command` 日志主题（本轮执行）

- 从 ULog 注册表与 SD 写入路径移除该主题；**DroneCAN 总线零命令发送不变**（安全功能，仅砍日志）。
- 效果预期：产生速率 37.6 → 约 27 kB/s，对 SD 稳态吞吐（≈45 kB/s，见 `TODO.md` 引用的 dropout 定量分析）余量 1.2× → 约 1.7×。实测结果以重跑采集为准。

### 第 2 层：文件预分配 / 整簇扩展（本轮评估结论：需 crate 层决策，不改代码）

- 现象对应：最长 65.5 ms 停顿的典型成因是写途中扩展 FAT 簇链（分配 + 卡分配单元操作）。
- 核查结果（2026-11-06）：固定 revision 的 `embedded-fatfs 518528c` 的 `File` 只有 `truncate`，**没有 `set_len`/预分配接口**；且写入器已是 `STAGING_BYTES=32 KiB` 攒批 + 512 字节对齐整块 flush——软件侧合并已到顶，文件扩展频率约为每 32 KiB 一次。
- 备选路径均被否决：顺序写零预留会破坏 `LOG_ENTRY.size` 与 pyulog 截尾解析；crate fork 违反固定依赖约束。**结论：软件侧无进一步动作，剩余停顿归第 3 层卡选型处理。**

### 第 3 层：卡选型判据（H-04 工程师输入，未开始）

- 消费卡后台 GC 是 65 ms 级尖峰的物理根源。A1/A2 评级卡（保证随机写 IOPS）或工业 pSLC 卡可把尾部长度压缩一个数量级。
- H-04 原"卡型号/布局/时延"输入升级为"按 A1/A2 或工业卡选型 + 实测写延迟分布"。这是唯一缩短尾部本身的手段；1–2 层只是绕开尾部。

### PX4 logger 对照（2026-11-07，[PX4 官方文档](https://docs.px4.io/main/en/dev_log/logging.html)；卡面 2026-11-07 确认为 A1 HC1）

| 维度 | PX4 文档口径 | 本项目实测（同板 H7 + 32 GB A1 HC1 卡） |
| --- | --- | --- |
| 默认主题集带宽 | ≈50 KB/s | 25.05 KB/s（主题集更小） |
| 决定性指标 | 4 KB 块最大写时间 / `fsync` 尖峰，**不是标签或均值** | ULog dropout 原始 ms + 记录间隔交叉核对 |
| 普通卡预期 | "多数卡每分钟多次数百 ms 停顿" | 300 s 内 17 次全部 ≤6 ms；712 s 内 48 次 ≤6 ms + **1 次 152 ms** |
| 标签 vs 实测 | PX4 按 sd_bench 逐卡实测分级，不按 A1/A2 标签 | 本卡有 A1 标签仍出现 152 ms 级尖峰：A1 保证随机读 IOPS，不保证无长写停顿；按 PX4 判据仍非"可靠卡"档 |
| 可靠卡档 | SanDisk Extreme U3 32GB：H7 均值 2900 KB/s、单块 8 ms，"几乎无 dropout"；Samsung EVO Plus 32GB：1900 KB/s、9–60 ms | 稳态 ≤6 ms 接近可靠卡档，但 152 ms 长尾未达 |
| 吸收手段 | F7/H7 更大缓冲 + 读缓存（数值未公布） | 168 KiB 队列（事件预留）+ 32 KiB 攒批 512 对齐写；25 KB/s 下 ≈6.7 s 余量 |
| 写失败处理 | 自动换新文件继续记 | 进入 Error 需手动重启（功能差异） |
| 可观测性 | 仅 ULog dropout 消息 | 另有 normal/event 丢弃计数 + 高水位 |
| 空间管理 | 轮转 + 自动清理（SDLOG_ROTATE/MAX_SIZE） | 无；卡满写失败 |
| 断电恢复 | 依赖 ULog 截尾解析 | 相同；实测断电日志完整可解析、无损坏 |

结论：稳态表现优于 PX4 对普通卡的预期；**A1 标签满足选型判据，但 152 ms 长尾说明标签不能替代 PX4 式逐卡写尖峰实测**——裁决依据应是实测分布（1012 s：1 次 152 ms，其余 ≤6 ms，事件 0）。按 PX4 的卡级经验（单块 8–60 ms 的可靠卡"几乎无 dropout"），换 SanDisk Extreme U3 / Samsung EVO Plus 级卡可基本消除该长尾。该对照作为窗口裁决依据之一。

### 第 4 层：结构化兜底（本文重点，最后才考虑）

仅在 1–3 层完成后，M1 联合负载复验仍超出 H-04 允许丢失窗口时评估。

**a. 双优先级队列**

- 设计：IMU/估计器记录走高优先级队列，CAN 诊断走低优先级队列；写入端先排空高优先级，低优先级仅在高优先级低于水位时服务。
- 收益：诊断洪峰永不挤掉关键记录；`logger_normal_dropped` 可归零（事件类本已为 0）。
- 代价：两套队列的水位、背压与丢弃计数语义；`rust_runtime_health` 需要区分两级丢弃；事件保留（dropout 前置、event 预留）逻辑要在两个队列上重推；M1/PL-a 的队列预算证据需重新采集。改动集中在 `log_queue.rs`/`sd_logger.rs`，估计 1–2 天实现 + 一轮板载复验。

**b. 裸块环形日志（弃 FAT）**

- 设计：绕过文件系统，SD 按固定 LBA 环形写入块头 + 记录，掉电后按序扫描恢复；离线工具解析。
- 收益：彻底消除文件系统抖动（分配/元数据/FAT 检查），写路径成为纯顺序块写。
- 代价：**推翻 PL-a 已过门证据**——可挂载 `.ulg` 文件、QGC/MAVLink 下载（LOG_REQUEST 语义）、断电可恢复记录、pyulog 直接解析全部重做；下载器与解析工具链同步重写。收益配不上代价，明确不建议，除非未来改用裸卡/大容量顺序记录的产品形态。

### 第 5 层：收口

- dropout 复验并入 M1 5 分钟联合负载，对照 H-04 允许丢失窗口判定；事件类丢失保持 0 是硬要求。
